# Tools

Everything around the codec that is not the harness in `bench/`: collecting pages, checking the
format, measuring in a kernel and on a phone, and drawing the results. Programs have a directory of
their own, scripts are at the top. The commands are in [docs/measuring.md](../docs/measuring.md).

| tool | what it does |
| --- | --- |
| [`collect/`](collect) | the page collectors: `seqlz-collect-resident` samples resident memory, `seqlz-import-raw` turns a `dd` of a zram device into a corpus, `seqlz-split-corpus` and `seqlz-sample-corpus` split it and draw samples |
| [`seqlz-ref/`](seqlz-ref) | two decoders written from [docs/format.md](../docs/format.md) alone, slow on purpose, in Python and in C. The tests and the fuzzers check `seqlz_decode()` against the C one, and `check.sh`, run by CI, checks the spec's table hashes and decodes pages `src/` compressed with the Python one |
| [`gen-tables/`](gen-tables) | `gen-tables.sh <out.c>` writes the codec's codes and decode tables as C, `seqlz_tables.c`, which every build of `src/` compiles: it builds `gen_seqlz_tables.c` with `src/seqlz_codes.c` and the code lengths for the build host, and runs it. CMake runs it, and so do the scripts that build `src/` without CMake; `-DSEQLZ_PAGE_BITS=14` for 16 KiB blocks |
| [`kernel-port/`](kernel-port) | `port.py` writes the codec into a Linux tree as the kernel would have it: `lib/seqlz/` with the tables built at compile time by a host program, `gen_seqlz_tables.c` of `gen-tables/`, from the code lengths of `seqlz_lengths.h`, `include/linux/seqlz.h` with only `seqlz_compress()` and `seqlz_decompress()`, Kconfig, a zram backend `seqlz` without the experiments of `zram-vm/`, `docs/format.md` as `Documentation/staging/seqlz.rst` (`format_rst.py`), and the code lengths as `gen-seqlz-lengths.py` makes them from `bench/seqlz_counts_4k.txt`, with the generator and the counts. `gen-seqlz-lengths.py` also writes the `.inc` tables of `src/`. `check.sh`, run by CI for x86-64, arm64, 32-bit arm and big-endian s390, builds that in a copy of a tree with W=1, compares the generated tables with the ones of `gen-tables/`, and runs checkpatch and kernel-doc on it. `kunit.sh` runs the KUnit tests port.py writes, `lib/seqlz/tests/seqlz_kunit.c`, in UML; CI runs them with KASAN and UBSan. `stress.sh` boots that kernel with KASAN, lockdep and UBSan in a VM: the corpus written to zram against the model's memory, swap thrash with every page compared, the zram selftests. `zcomp-split.sh` applies zram's series that splits the contexts into compression and decompression to a tree; `port.py` then writes the backend in that form |
| [`samecode/`](samecode) | `samecode.sh` builds the kernel copy of two revisions or worktrees with gcc and clang for x86-64 and clang for arm64, and names the functions whose machine code differs, for a refactor that should not change it. The phone's module, built from `src/` with NDK r21e's clang 9, is not in it |
| [`zram-vm/`](zram-vm) | `run.sh` builds a kernel with seqlz as a zram backend, boots it in a VM, and measures zram's reads and writes, or with `MODE=swap` the whole page fault; with `VARIANTS` other builds of the codec as backends of their own in the same kernel; with `wkdm` in `ALGOS` Apple's C version of WKdm as backend `wkdm`, downloaded from xnu and checked by SHA-256, not in this repository; `variants.py` gives each variant against its base, in µs and %, next to a copy of the base |
| [`zram-phone/`](zram-phone) | zram's writes and reads in the Mi 9T's own Linux 4.14: `build.sh` makes a module of the codec for that kernel (`OPT` and `ALIGN` for other flags), with the phone's symbol CRCs (`crcs.py`, `patch_versions.py`), `run.sh` runs `zramphone` on each codec alone, in turns, logs the clocks and temperatures around every run and can fix the memory's clocks and stop Android, `summary.py` gives the mean and the range per codec |
| [`swap-fault/`](swap-fault) | the whole page fault on a running Linux as root, e.g. a rooted phone |
| [`phone-apps/`](phone-apps) | the app launch test on a rooted Android phone: 25 apps in turn, zram on each codec, a reboot before every run |
| [`phone-dump/`](phone-dump) | zram dumps of a rooted phone in use: `session.sh` reboots it, runs `workload.sh` (browsers, videos, maps, the camera, documents, `monkey`) and writes the zram device; `swapmap` gives every page its process and mapping, `attribute.py` puts them into the corpus |
| [`android-emu/`](android-emu) | a zram dump from the Android 17 emulator, with 4 KiB or 16 KiB pages: its apps in turn while `hog` holds the RAM |
| [`swap-bursts/`](swap-bursts) | `seqlz-swap-bursts`: samples `pswpin`, groups the swap-ins into bursts, and gives `r`, the reads per write of the score |
| [`seqlz-bound/`](seqlz-bound) | per kind of field the bits a dump's pages take, next to their entropy, layouts of the offset classes priced on real sequences, `OWN` with a code by the symbol before, priced on level 3's descriptions (`owndump.c`, `own_context.py`), and a second and third repeat offset priced on the sequences of any level (`seqsrep.c`, `reps.py`) |
| [`seqlz-branches/`](seqlz-branches) | which branches of the decoder mispredict on pages it sees once, as in a swap-in: `perf stat` per decode, and the mispredicted branches by source line from the CPU's branch records |
| [`seqlz-worst/`](seqlz-worst) | the worst case: `seqlz-worst` counts the instructions of every page of a corpus and writes made-up pages that are slow, `cost_fuzz.c` searches for slower ones, also for `lz4`, `lzo-rle` and `zstd`; the level is `--level` and `COST_LEVEL`, 2 by default, or one of the targets `seqlz_1` to `seqlz_3` with kernel flags. The slowest pages found are in [`seqlz-worst/pages/`](seqlz-worst/pages) |
| [`seqlz-compress/`](seqlz-compress) | `compress.c`: writes each 4 KiB page file compressed at each level, `<page>.1` to `<page>.3`, each decoded again first; for checking a byte count in the docs, and for `seqlz-ref/check.sh` |
| [`check-links.py`](check-links.py) | every relative link and `#anchor` in the Markdown files must resolve, run by CI |
| [`quick-bench.sh`](quick-bench.sh) | the fast benchmark for trying out a change: exact sizes on the whole corpus, times on a sample of 20 000 pages in 5 processes |
| [`bench-dict.sh`](bench-dict.sh) | trains a dictionary on one dump and measures every codec with and without it on another |
| [`plot-codecs.py`](plot-codecs.py) | memory against time, from the logs of `zram-vm/run.sh` |
| [`plot-swap-fault.py`](plot-swap-fault.py) | the same for the whole page fault, from `zram-vm/run.sh` with `MODE=swap` and from `swap-fault/` |
| [`phone-cores.sh`](phone-cores.sh) | the codecs on the cores of a phone over `adb`, in userspace and without root: each codec alone in its own process, pinned to one core, in rounds; cleans up the phone after |
| [`plot-cores.py`](plot-cores.py) | memory against the time to write and to read cold, one panel per core and direction, from the log of `phone-cores.sh` |
| [`plot-readme.py`](plot-readme.py) | the README's chart: the three levels against `lz4`, `lzo-rle` and `zstd` 3 and the hull of them, the mean over several `seqlz-score` outputs of `zram-vm/run.sh` logs |
| [`plot-zstd-levels.py`](plot-zstd-levels.py) | `seqlz-2` against `zstd` at each level, from `zram-vm/run.sh` logs with `MODE=swap` and `zstd:<level>` codecs |
| [`plot-devices.py`](plot-devices.py) | memory against time on several CPUs, one row per CPU |
| [`plot-speed.py`](plot-speed.py) | the first chart of [docs/seqlz.md](../docs/seqlz.md#the-result-lz4s-time-zstds-size-almost): cycles in a hot loop, and write, cold read and memory in the kernel VM |
| [`retrain-tables.py`](retrain-tables.py) | seqlz's tables trained again: the counts, their literal tables in the committed order, the `.inc` files of `src/` and the tables' SHA-256 in `docs/format.md`, in one step |

The plot scripts need `matplotlib` and the Noto Sans font.
